# 포트 (리스닝 포트 확인·종료)

`main/features/ports`(lsof 실행·파싱) + `renderer/features/ports`(섹션)

> 목적: "포트가 이미 사용 중" 이 떴을 때 터미널에서 `lsof` 로 찾아 `kill` 하던 일을 화면에서 끝낸다.
> 남은 개발 서버를 정리하는 용도라, **내가 띄운 것**을 빨리 찾는 것이 화면의 우선순위다.

## lsof 함정 (전부 실측 2026-09-23)
- ⚠️ **`-p` 에 넘기는 PID 는 20개까지다.** 그보다 많으면 **에러 없이 빈 결과**를 준다
  (20개 → 20건, 30개 → 0건). cwd 가 통째로 비는 증상으로만 보여 원인을 찾기 어렵다 →
  `CWD_CHUNK = 20` 으로 잘라 부른다.
- ⚠️ **기본 출력은 명령 이름을 9자에서 자른다**(`com.docke`·`ControlCe`). `-F` 필드 포맷으로 받으면
  온전하다(`com.docker.backend`). 그래서 사람이 읽는 출력이 아니라 `-F pcLn` 을 파싱한다.
- ⚠️ **같은 포트가 IPv4·IPv6 로 두 줄씩 온다.** 묶지 않으면 목록이 두 배로 보인다 →
  `(pid, port)` 를 키로 묶고 주소는 배열로 모은다(44줄 → 41개).
- ⚠️ **lsof 는 접근 못 하는 프로세스가 있으면 0이 아닌 코드로 끝내면서도 정상 출력을 준다.**
  에러라고 버리면 목록이 통째로 빈다 → `execFile` 콜백에서 `err` 를 무시하고 stdout 을 쓴다.
- ⚠️ 포트는 **마지막 콜론 뒤**다 — IPv6(`[::1]:5173`)는 콜론이 여러 개라 첫 콜론으로 자르면 안 된다.
- 속도는 걱정하지 않아도 된다: 리스닝 목록 0.06초, cwd 배치 0.02초.

## 프로젝트 매칭은 등록이 아니라 cwd 로 한다
프로세스의 작업 디렉터리(`lsof -a -p <pids> -d cwd -F pn`)를 프로젝트 레지스트리의 `localPath` 와
맞춘다. **`Project` 에 포트 필드를 만들지 말 것** — 사용자가 등록·관리해야 하고 실제 포트와 어긋난다.

- **하위 경로까지 인정**한다(개발 서버는 보통 하위 폴더에서 뜬다). 여러 개가 걸리면 **가장 깊은 것**을
  고른다 — 상위 폴더도 프로젝트로 등록돼 있을 수 있다.
- ⚠️ `projects/store.ts` 의 `findProjectByPath` 는 **정확 일치**라 여기엔 못 쓴다. `listProjects()` 를
  받아 직접 prefix 비교한다(`cwd === base || cwd.startsWith(base + '/')` — `projects-old` 같은 옆 폴더를
  삼키지 않게 `/` 를 붙여 비교할 것. `lsof.test.ts` 가 고정한다).
- 매칭된 항목을 목록 맨 위로 올린다.

## 종료
- 기본 **SIGTERM** → 1.2초 뒤 생존 확인 → 살아 있으면 화면이 **[강제 종료](SIGKILL)** 를 이어서 묻는다.
  바로 확인하면 정리 중이라 항상 살아 있는 것으로 보인다.
- 생존 확인은 `process.kill(pid, 0)`(신호를 보내지 않고 존재만 확인).
- `EPERM`(다른 사용자·시스템 소유)·`ESRCH`(이미 없음)를 구분해 문구를 다르게 준다.
- **One App 자신(`process.pid`)은 main 이 거부**한다 — UI 만 믿지 않는다.

## 보호 표시(`guarded`)는 감추는 것이 아니다
macOS 구성요소(`ControlCenter` 가 AirPlay 로 **7000·5000** 을 잡는다·`rapportd`·`sharingd` …)와
root/시스템 계정(`_` 로 시작) 소유, 그리고 One App 자신에 자물쇠를 붙이고 **확인 다이얼로그를 한 번 더**
띄운다. ⚠️ **목록에서 빼지 말 것** — "왜 7000 이 쓰이지" 를 확인하는 것도 이 화면의 쓸모다.

## 목록은 **프로세스 단위**로 묶고 기본은 '개발' 만 보인다
포트마다 한 줄이면 46행이 나온다(2026-09-23 실측) — Docker 6포트·Vite 3포트·언어 서버 3포트가 각각
여러 줄을 차지한다. 그래서 **PID 로 묶고**(24행) 포트는 칩으로 나열하며, 상단 세그먼트로
**`개발 | 전체`**(기본 개발 → 9행)를 가른다.

- ⚠️ **특정 포트만 닫는 방법은 없다** — 어차피 프로세스를 죽여야 하므로 묶어도 할 수 있는 일이 줄지 않는다.
- ⚠️ **검색은 항상 전체를 대상으로** 한다 — '개발' 에 가려진 것도 포트 번호로 찾을 수 있어야 한다
  (`7000` 을 치면 필터가 '개발' 이어도 ControlCenter 가 나온다).
- `dev` 판정은 main 이 계산해 내려준다(규칙이 한 곳). 프로젝트 매칭 OR 개발 런타임 이름 OR 컨테이너 런타임.
- ⚠️ **런타임 이름 정규식 끝에 `\b`(단어 경계)가 반드시 있어야 한다** — 없으면 `go` 가 **"Google Chrome"**
  의 Go 에 걸려 브라우저가 개발 서버로 분류된다(2026-09-23 실측 버그, `lsof.test.ts` 가 회귀를 막는다).
  짧은 이름(`go`·`mvn`)일수록 위험하다.
- 완벽한 분류는 불가능하므로(언어 서버·IDE 헬퍼도 node·java 로 뜬다) **감추는 것이 아니라 기본값일 뿐**이다.
  개수는 세그먼트 라벨 안에 넣는다(`개발 9 | 전체 24`) — 옆에 따로 적으면 **문구 길이가 변해 새로고침
  버튼이 좌우로 밀린다**(2026-09-23 사용자 지적).
- ⚠️ **목록만 스크롤시킬 것**(`.ports { height: 100% }` + `.ports__list { flex: 1; overflow-y: auto }`).
  섹션 전체가 스크롤되면 목록이 길 때 `.main` 에 스크롤바가 생기며 **콘텐츠 폭이 10px 줄어 툴바가
  5px 밀린다**(실측). 덤으로 검색창이 항상 보인다.

## 비고
- 데스크톱 전용(`ipcMain.handle`) — 폰에서 프로세스를 죽일 이유가 없어 `handleShared` 로 열지 않는다.
- 렌더러는 `window.oneApp.ports?.` **옵셔널**로 부른다(구 preload·폰 셸에는 없다).
- 파싱은 전부 순수 함수(`lsof.ts`)로 두고 실행만 `ipc.ts` 에 있다 — 표본과 규칙은 `lsof.test.ts`.
